<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser -> contact forms | Untrusted names, emails, company values, selectors and free-text message enter client form state. |
| contact forms -> `/api/contact` | Client serializes the form into a public JSON POST. |
| `/api/contact` -> Resend/email HTML | Validated visitor text reaches the existing escaped email builder and external mail provider. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | `src/components/contact-form.tsx` payload serialization | high | mitigate | Preserve the existing field names, server Zod validation and `escapeHtml`; tests assert the exact payload shape rather than trusting client labels. |
| T-01-05 | Denial of service | `/api/contact` POST | medium | mitigate | Keep the hidden honeypot and bounded rate limiter untouched; no new bypass or alternate submission path is introduced. |
| T-01-06 | Information disclosure | contact copy and status/log paths | medium | mitigate | Use only public contact signals, never secrets or provider credentials; keep existing structured error logging and generic user-facing failures. |
| T-01-07 | Repudiation/usability | form labels, status and live regions | medium | mitigate | Preserve stable accessible names, `role=status`, `aria-live=polite`, visible focus and explicit next-step error copy while changing wording. |
| T-01-SC | Tampering | package-manager installs | high | mitigate | This plan adds no dependency; existing lockfile and installed packages remain unchanged. |
</threat_model>
