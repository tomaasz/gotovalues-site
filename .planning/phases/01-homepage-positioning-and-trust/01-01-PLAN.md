<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser -> rendered homepage/forms | Public visitor controls free-text form values and sees server-rendered marketing content. |
| title-block client -> `/api/contact` | Browser serializes untrusted form data into the existing contact route. |
| contact route -> email HTML builder | User-controlled fields cross into the existing escaped email representation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `src/lib/contact.ts` email builder | high | mitigate | Preserve existing `escapeHtml` path and test the unchanged payload/email boundary; this phase changes copy only. |
| T-01-02 | Denial of service | `src/app/api/contact/route.ts` contact POST | medium | mitigate | Preserve server-side honeypot and bounded rate limiter; do not add a client-only spam control or bypass the route. |
| T-01-03 | Information disclosure | homepage content and contact logs | medium | mitigate | Keep secrets, environment values, invented customer details and sensitive operational data out of `siteContent`, tests and logs. |
| T-01-SC | Tampering | package-manager installs | high | mitigate | No package installation is planned; keep the existing lockfile and dependencies untouched. |
</threat_model>
